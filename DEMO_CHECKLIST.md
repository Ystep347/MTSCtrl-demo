# Проверка перед защитой: живые данные, уведомления и ИИ

Для хакатона нужен сквозной прогон по презентации, а не формальная сертификация.
Серверные тесты автоматизированы; отдельно проверяем то, что увидит координатор.

## Что показываем

По умолчанию открыт режим **«Симуляция МТС»**: пять направлений и 44 вымышленных
телеком-инцидента. Исполнители, ID, статусы, приоритеты и сроки исходного массива
сохранены. Переключатель «Показать исходные данные» возвращает материал организаторов.
`data/incidents.json` и справочник атрибутов не переименованы и не переписаны.
`data/mts-simulation.json` — отдельная копия в том же формате для демонстрации.

## Автоматическая проверка

```sh
npm run build
npm test
npm run validate
npm run test:local
npm run test:auth
```

Текущая проверенная база: 87 тестов, 14 HTTP-сценариев данных и 9 сценариев самостоятельного входа.
Проверка не меняет опубликованные общие данные.
Ручной прогон v13 также выполнен в двух вкладках: критический, назначение
координаторам, изменение срока, решение. Обе вкладки получили обновления
из одного JSON без перезагрузки; плашка восстановления появилась в обеих.

## Живая проверка изменения JSON на своём компьютере

Нужен Node.js 24+. Остановите обычный `npm run dev`, если он занимает порт 4173.
В первом терминале, находясь в папке проекта:

```sh
npm run demo:scenario -- prepare
npm run demo:scenario -- serve
```

Откройте http://localhost:4173 в двух вкладках/окнах. Демо-сервер использует
`local-data/defense-demo/incidents.json` и отдельную SQLite. Все команды ниже
меняют именно этот файл. Формат записей совпадает с исходной выгрузкой.
Режим «Симулировать событие» на сайте не включайте: он замораживает одну вкладку.

Во втором терминале выполняйте команды по очереди. После каждой подождите
до следующего опроса — обычно до 5 секунд при доступной сети и активной вкладке.

| Шаг | Команда | Что должно быть видно в обоих окнах |
|---|---|---|
| Новый критический | `npm run demo:scenario -- critical` | Появился INC990000000001, 45 записей; он в критических и у координаторов; видимое уведомление |
| Назначение координаторам | `npm run demo:scenario -- coord` | Исследование назначено координаторам, находится в двух группах; null-дедлайн не стал просрочкой |
| Изменение срока | `npm run demo:scenario -- deadline` | У нового критического до срока около минуты; время обновилось и событие появилось в журнале |
| Восстановление | `npm run demo:scenario -- resolve` | Критический ушёл из активных групп; появилась зелёная плашка решения; запись доступна в решённых |
| Рост приоритета | `npm run demo:scenario -- high` | Существующий высокий инцидент стал критическим; появился сигнал о повышении приоритета |
| Повторный прогон | `npm run demo:scenario -- reset` | Снова исходные 44 демонстрационные записи |

`npm run demo:scenario -- status` печатает текущие счётчики без изменения файла.
Исполнители исходных 44 записей остаются прежними. У нового инцидента используется
тот же учебный исполнитель, что в первой записи, и отдельный вымышленный sysId.

Проверьте также поиск, фильтр продукта, ночную тему, видеостену, перезагрузку
одного окна и пустую группу. Новые события должны сохраняться в общем журнале.
Браузер может ограничивать таймеры фоновой вкладки: для проверки двух читателей
держите оба окна видимыми, а не свёрнутыми.

## Как повторить на опубликованном сайте

Сайт не читает файл с вашего компьютера автоматически. Редактор может после
каждой команды загрузить `local-data/defense-demo/incidents.json` через импорт,
а второе устройство показывает изменения после очередного опроса. Это изменит
общую учебную базу для всех посетителей. После прогона восстановите исходный файл
через импорт. Альтернатива — настроенный общий HTTPS-источник JSON.

## Собственный вход

Откройте `/login` в отдельном браузере: создайте личный аккаунт, выйдите и
войдите снова. Дашборд доступен гостю, вопрос помощнику — после своего входа.
Проверьте, что новый координатор не видит импорт и не имеет доступа к
`/api/auth/accounts` и `/api/assistant/settings`. Редактор назначает права
на `/account` (начальная выдача по AUTHENTICATION.md). Не создавайте общий пароль.

## ИИ

Обычный вопрос в v14 берёт данные на сервере. Проверьте отметку версии
и числа записей под ответом. Временная симуляция вкладки обозначается отдельно
и использует только анализ по правилам.

Войдите и спросите: «Что сейчас требует внимания?», «Объясни INC990000000001»,
«Что назначено координаторам?». Ответ должен ссылаться на текущие данные,
обозначать учебную симуляцию и не придумывать настоящую причину сбоя.

До подключения Яндекса это анализ по правилам. Настоящий ИИ подтверждается
успешным ответом с `provider=yandex`, а не наличием настроек или работающим полем
вопроса. На текущем этапе реальный вызов Яндекса ещё не подтверждён.

## Переход в ITSM

1. Выберите инцидент и нажмите **«Открыть в SimpleOne · демо»** в правой
   панели или в полной карточке. В новой вкладке откроется учебный стенд.
2. Сверьте ID, продукт, назначение, статус и срок с выбранной карточкой.
   Повторите переход после переключения на исходную выгрузку.
3. Запустите сценарий **«Новый критический инцидент»** и откройте его в
   SimpleOne. Учебная карточка покажет снимок из текущей вкладки дашборда.

Стенд работает в режиме просмотра. Для подключения корпоративной системы
понадобится её адрес и доступ.
