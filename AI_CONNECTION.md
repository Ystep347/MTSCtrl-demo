# Подключение настоящего ИИ Яндекса

Срез v15: сервер и защищённая форма подключения подготовлены. API-ключа
Яндекса и ID каталога в опубликованном окружении пока нет. Настоящий ответ
модели не подтверждён. Созданный технический ключ шифрования не заменяет
API-ключ провайдера и не даёт доступа к Яндексу.

## Что нужно сделать один раз в облаке команды

Нужен доступ к Yandex AI Studio / Yandex Cloud команды, облако и каталог,
активный платёжный аккаунт и API-ключ с разрешением вызывать текстовую модель.
Доступность модели и условия оплаты проверьте в своём каталоге.

Официальные инструкции:

- https://aistudio.yandex.ru/ru/docs/ai-studio/quickstart/
- https://aistudio.yandex.ru/ru/docs/ai-studio/operations/get-api-key/

Выпустить рабочий ключ без доступа к облачному аккаунту команды невозможно.
Пароли Яндекса, одноразовые коды и секретный API-ключ не отправляйте в чат,
презентацию или ZIP. Создание облачного аккаунта и принятие платных условий
выполняет владелец команды.

## Подключить на сайте без пересылки ключа в чат

1. Войдите своим аккаунтом Фокуса с ролью редактора. Если это первый редактор,
   выполните начальную выдачу прав по AUTHENTICATION.md.
2. Откройте «Подключение ИИ» в профиле или `/ai-settings`.
3. Укажите API-ключ, ID каталога и выберите доступную вам модель.
4. Нажмите «Сохранить подключение». Поле ключа очистится: сохранённый секрет
   не возвращается из API и не показывается при повторном открытии страницы.
5. Нажмите «Проверить ответ». Это один запрос по текущим учебным инцидентам;
   при рабочем подключении он может расходовать квоту Яндекса.
6. Успех — сообщение о настоящем ответе модели и `provider=yandex`, `mode=llm`.
   Сохранённые настройки или ответ по правилам не считаются подтверждением ИИ.

Ключ используется только сервером для запросов к API Яндекса. В базе хранится
шифротекст AES-GCM-256, ключ шифрования `AI_CONFIG_ENCRYPTION_KEY` находится
отдельно в окружении сервера. В текущем опубликованном сайте он уже подготовлен.
Не меняйте его случайно: без прежнего ключа сохранённые настройки не расшифровать.
После переноса проекта настройте новый ключ шифрования и сохраните API-ключ
Яндекса повторно. Секреты и рабочая база в ZIP не входят.

Полная пара переменных `YANDEX_API_KEY` + `YANDEX_FOLDER_ID`, если задана
непосредственно в серверном окружении, имеет приоритет над настройками формы.
Страница сообщает об этом. Только наличие параметров не подтверждает их валидность.

## Проверка на своём компьютере

Для формы подключения:

1. Запустите `npm run ai:prepare`: он создаёт только локальный ключ шифрования
   в игнорируемом `.env` и не печатает его. Уже существующий ключ не меняется.
2. Запустите или перезапустите `npm run dev`, создайте свой аккаунт.
3. Назначьте редактора: `npm run auth:editor -- ВАШ_ЛОГИН`.
4. Откройте `/ai-settings`, сохраните ключ/каталог и проверьте ответ как описано выше.

Альтернатива — заполнить серверные переменные в локальном `.env`:

```dotenv
YANDEX_API_KEY=
YANDEX_FOLDER_ID=
# Необязательно; по умолчанию: gpt://<folder>/aliceai-llm
YANDEX_MODEL_URI=
```

`gpt://` — формат URI модели в API Яндекса; это не обращение к OpenAI.
`npm run ai:check` проверяет только переменные окружения, без запроса модели.
`npm run ai:check -- --live` отправляет один настоящий запрос по учебным данным.
Успех CLI: `provider=yandex`, `verified=true` и непустой ответ.
CLI не читает ключ из зашифрованной D1/SQLite: для настройки через форму
используйте кнопку «Проверить ответ» на сайте.

## Откуда модель берёт факты

Обычный запрос:

```json
{
  "question": "Что требует внимания?",
  "contextMode": "server",
  "context": {"view": "mts-demo", "selectedId": null},
  "history": []
}
```

`view`: `mts-demo` или `source`. Сервер сам читает общую базу/источник,
применяет выбранное представление и вычисляет контекст. Ответ содержит
revision, version, total, mode, view и stale. Обычная симуляция МТС передаётся
модели с явным признаком учебных событий.

При ошибке источника используется помеченный сохранённый снимок; без пригодных
данных возвращается 503. Удалённая выбранная карточка возвращает 404.
Snapshot браузера в обычном запросе отклоняется. `contextMode=client_demo`
допускает временные данные вкладки только для анализа по правилам, без LLM.

Вопрос требует собственного входа. Есть ограничение 12 запросов в минуту
на пользователя в пределах экземпляра Worker. Централизованной квоты ещё нет.
Проверьте неизвестный ID, отсутствие срока, обновление назначения и отказ
провайдера. Тесты с имитацией API не заменяют проверку настоящего Яндекса.
