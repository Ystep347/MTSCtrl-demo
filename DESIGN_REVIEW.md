Галерея сохраняет предыдущие варианты; концепции A–D теперь собираются из

Галерея `/designs` показывает четыре направления до выбора основного дизайна.
`web/index.html`, `web/styles.css` и обработчики API не изменены.
В `web/app.js` исправлено обновление списка продуктов после локального демособытия:
добавленный продукт теперь сразу доступен в фильтре.
Каждая `/concept/<key>` собирается из действующего интерфейса, использует его
API, поиск, фильтры, карточки, историю, авторизацию и демонстрационные сценарии.
Дополнительные CSS и JS загружаются только на страницах концепций.

| classic | МТС Классика | Светлый фон, четыре группы, красный акцент |

`?demo=1` добавляет один критический инцидент штатным локальным обработчиком
демонстрации после получения исходных данных. Он не сохраняется в D1; статус
источника явно говорит об изменениях только на текущем экране. Миниатюры
используют тот же сценарий и параметр `thumbnail=1`. Все четыре исходных набора
одинаковы. Переход к реальным данным возможен через «Вернуться к выгрузке».

Режим фокуса скрывает второстепенные панели, подпись и нижний колонтитул.
Он не отключает поиск, фильтры, карточки, помощника, обновление данных или права.
В галерее есть переключатель ширины телефона, самостоятельные ссылки и
переключение A/B/C/D. Галерея ничего не записывает в общее хранилище.

## Новые концепции E–G

- E `/concept/pulse`: очередь по объяснимым правилам, локальная хронология из шести шагов, новые/просмотренные события, сводка передачи смены.
- F `/concept/orbit`: интерактивная карта продукт → назначенные команды по реальным данным; это не карта инфраструктурных зависимостей.
- G `/concept/command`: тёмный рабочий стол с очередью, встроенной карточкой, клавишами J/K и командной палитрой Ctrl K.

Новые страницы получают нормализованный снимок через существующий API и используют канонические функции групп. Запись инцидентов в этих концепциях отсутствует. Наблюдение и пометки просмотра хранятся только в браузере. Сводки и объяснение очереди строятся по проверяемым правилам и не выдаются за ответ LLM или статистический прогноз.

`lib/workbench.mjs` содержит чистую логику очереди, сводок, карты и демонстрации. Тесты проверяют пересечения групп, отсутствие активной просрочки у исследования, неизменность исходного набора при перемотке и честную маркировку сводок. Миниатюры загружаются лениво, длинные очереди раскрываются по запросу, ввод поиска обрабатывается с небольшой задержкой.

Оценка готовности на `/guide.html#readiness`: около 55% полной версии и примерно 70% демонстрации кейса. Это субъективная оценка объёма работ, а не автоматически измеренная метрика. Полная версия включает запрошенные пользователем аккаунты и роли; для защиты по ТЗ приоритетны реальная модель, переход в ITSM и проверка реакции на изменения файла.
