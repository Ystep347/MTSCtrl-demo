## Единый рабочий сценарий и JSON API SimpleOne · 21.11.2026

- Гость сразу входит в общий интерфейс аналитика-координатора. Для
  регистрации и обычной работы выбор роли убран. Старые аккаунты
  продолжают работать, право редактора выдаётся отдельно.
- Аналитик передаёт активные инциденты из трёх рабочих групп исполнительным
  командам. Приложение показывает подтверждение SimpleOne либо ошибку
  доставки и повторную отправку. Гость использует учебный JSON API.
- Решение подтверждает аналитик в Фокусе или исполнительная команда в
  SimpleOne. Из решённого состояния можно закрыть инцидент или отправить
  на расследование. После фиксации результата расследования карточка
  доступна для закрытия. События и решение сохраняются в истории.
- AI-Штурман и чат показывают подтверждённые связи, возможное сходство и
  основания для проверки назначений. Видеостена остаётся полноэкранной,
  с группами и компактным графиком.
- Миграция `0004_simpleone_lifecycle.sql` сохраняет рабочее состояние,
  доставку и историю. Для живого SimpleOne нужны серверные настройки,
  соответствие команд системным ID и правило отправки обратного события.
- Проверены сборка, 101 тест и 27 HTTP-проверок. В Chrome прошли гостевой
  вход, JSON-передача, подтверждение обеими сторонами, обе ветки закрытия
  и видеостена 5120×1440. Локальный предпросмотр на порту 4174 использует
  учебный SimpleOne. Рабочий PATCH и обратное событие проверены на
  тестовых ответах.

## Рабочие роли, видеостена и передача инцидентов · 21.11.2026

- Группы открываются по умолчанию. Пустые группы скрываются, появившиеся
  встают слева. Постоянное уведомление и красная подсветка сохраняются после
  назначения до взятия в работу или отсрочки аналитиком. Состояние общего
  назначения хранится отдельно от JSON и обновляется в других сеансах.
- Общий экран использует всю ширину и высоту окна. На нём остались группы
  в фокусе и компактный сглаженный график поступления и восстановления.
  У стены есть полноэкранный режим и счётчики скрытых карточек в длинных группах.
- При регистрации и гостевом входе доступны координатор и аналитик.
  Координатор назначает команду либо конкретного аналитика и видит Team Load,
  список команд для внимания и структуру инцидентов. Аналитик выбирает
  сортировку по релевантности, новизне, сроку SLA или продукту и фильтрует
  карточки по продукту и SLA. В его карточке остаются AI-Штурман,
  похожие завершённые инциденты и карта ИнциДНК на рабочем экране.
- ИнциДНК показывает подтверждённые связи по существующим ID и отдельный
  слой возможных связей. Признаки мастер-инцидента, дубля, корневого,
  причины и дочерней записи показаны у выбранной карточки.
- Оценка эскалации доступна обеим ролям. По названию, описанию, дате создания
  и сроку рассчитывается объяснимая оценка. Подключённый Яндекс может
  уточнить оценку и релевантность, а также дополнить автоматически
  собранный отчёт о передаче. Прогноз отмечен как оценка.
- Миграция `0003_workflow.sql` добавляет назначения и настройки команды
  аналитика. Локальные учётные записи созданы в существующей базе.
  Пароли сохранены в `local-data/DEMO_ACCOUNTS.txt`, путь исключён из Git.
- Прошли сборка, валидация, 99 тестов и 27 HTTP-проверок. В Chrome проверены
  обе учётные записи, гостевая цепочка в трёх вкладках и отсутствие
  прокрутки у видеостены на 5120×1440 и 390×844.
- Локальный предпросмотр доступен на http://127.0.0.1:4174/.
  Провайдер Яндекса в этом предпросмотре не настроен. Интеграция оценок и
  черновиков проверена на тестовых ответах модели. Исходные 44 записи

## Изменения v15 — отдельный вход и настройка Яндекса

- `/login` обслуживает собственные вход и регистрацию. Для обычной работы
  команды внешний аккаунт не нужен. Нет общих или автоматически созданных паролей.
- Пароли: bcrypt с солью и стоимостью 12; сеанс 8 часов, случайный токен,
  его SHA-256 в базе, HttpOnly/Secure/SameSite cookie в HTTPS, серверный выход.
- Саморегистрация даёт только координатора. Изменение ролей и API-ключа
  доступны редактору; клиентские роли и email не используются для повышения прав.
- Ограничения попыток входа и регистрации сохраняются в базе. Изменяющие
  запросы входа, ролей и настройки ИИ требуют совпадения Origin.
- `/account` — выдача ролей. Начальная выдача редактора описана в AUTHENTICATION.md.
- `/ai-settings` сохраняет ключ/каталог с AES-GCM-256 в базе. Ключ шифрования
  хранится отдельно в окружении сервера. Секрет не возвращается из API.
- Настоящего API-ключа Яндекса по-прежнему нет: созданы только технические условия
  безопасного подключения. Наличие сохранённых настроек не равно проверенному ответу.
- Локально по настоящему HTTP проверены регистрация, вход, смена сеанса,
  права, вопрос помощнику, перезапуск, выдача редактора, шифрование и выход.
- В браузере проверены свои формы входа/регистрации и честная проверка ИИ без ключа.

## Изменения v14 — серверный контекст помощника

Обычный вопрос читает общую базу/источник на сервере. Переданный браузером
snapshot отклоняется. Вид mts-demo применяется сервером с явной пометкой
симуляции. В ответе видны версия и число записей. При ошибке источника
сохранённый снимок явно обозначается устаревшим. Временные данные вкладки
обрабатываются только в client_demo с анализом по правилам, без обращения к LLM.
Кнопка проверки помощника отправляет вопрос, а не только читает настройки.
Команда `npm run ai:check -- --live` готова для одного реального вызова Яндекса.
Настоящего ключа/каталога и подтверждённого ответа модели пока нет.

В браузере с локальным тестовым редактором проверены обычная сводка
(44 записи, серверная версия) и локальная симуляция (45 записей, явная пометка).
Рабочая оценка хакатонного MVP: около 80%, подробности REQUIREMENTS_STATUS.md.

## Что ещё не подтверждено или не подключено

1. **Настоящая генерация Яндекса.** Нет рабочего ключа и folder ID. Тесты эмулируют ответы провайдера; реальный вызов ими не подтверждён.
2. **Реальный переход в ITSM МТС.** Нет адреса/схемы URL и учётной записи для проверки. Шаблон `itsm.example` используется только в тестах.
3. **Корпоративная авторизация.** Нет SSO МТС, справочника ролей/сотрудников и серверных прав по подразделениям. Базовый логин/пароль уже независим от платформы. Нет восстановления пароля, MFA и приглашений.
4. **Непрерывная интеграция с ITSM.** Настроенный источник читается при запросах клиентов; нет фонового планировщика/webhook и действий назначения в ITSM.
5. **Достоверные ИИ-рекомендации по командам.** Нужен справочник владельцев сервисов; текущая команда известна из выгрузки, другая команда не выдумывается.
6. **Производственная эксплуатация.** Нет полной проверки нагрузки, централизованных квот ИИ, мониторинга, резервного восстановления и корпоративного разграничения данных.
7. **Физические устройства и мобильный UX.** Живой прогон изменения JSON проверен в двух вкладках браузера: новый критический, назначение исследования координаторам, новый срок, решение с зелёной плашкой в обеих вкладках. Проверка на двух физических устройствах команды остаётся перед защитой.

## Граница между демонстрацией и общими данными

«Симулировать событие» меняет только текущую вкладку и явно замораживает её
на демонстрационных данных. Для доказательства обновления у всех меняйте
настоящий локальный JSON, загружайте новый JSON редактором либо меняйте
настроенный общий источник. После демо вернитесь к исходной выгрузке.

Ручной прогон v13 выполнен на отдельном локальном JSON и SQLite. Рабочая
публичная база не изменялась. Учебная ITSM-страница и переключение к оригиналу
также проверены в браузере.
