# Свои аккаунты: вход без внешнего сервиса

Срез v15, 21.11.2026. В Фокусе работают собственные регистрация, логин/пароль,
выход и роли. Ключ Яндекса для входа не нужен. Никаких общих паролей или
автоматически созданных рабочих аккаунтов в исходниках нет.

## Что делает участник

1. Открывает `/login` и выбирает «Создать аккаунт».
2. Указывает своё имя, логин или почту и пароль. Короткий логин содержит
   3–32 символа и начинается с латинской буквы. Можно использовать
   латинские буквы, цифры, точку, дефис и подчёркивание.
   Почта используется как идентификатор для входа. Подтверждения письмом пока нет.
   Пароль должен содержать не менее 10 символов. Если он слишком длинный,
   форма попросит сократить его.
3. Получает роль координатора. Может смотреть дашборд и спрашивать помощника.
4. Для нового сеанса использует тот же логин и пароль. Кнопка «Выйти» отзывает
   сеанс на сервере. Аккаунт остаётся в базе после закрытия браузера.

## Кто может что делать

| Действие | Гость | Координатор | Редактор |
|---|---|---|---|
| Дашборд, карточки, общий экран, учебные сценарии | Да | Да | Да |
| Вопрос помощнику | Нет | Да | Да |
| Общий импорт/экспорт исходных данных | Нет | Нет | Да |
| Назначение ролей на `/account` | Нет | Нет | Да |
| Настройка API Яндекса на `/ai-settings` | Нет | Нет | Да |

Регистрация всегда создаёт координатора. Присланные клиентом `role` и email
не дают расширенных прав. Роль проверяется на сервере при каждом запросе.
Редакторам доверены общая выгрузка, роли и подключение ИИ: выдавайте эти права
только участникам команды, которым они нужны. Это две роли одного общего
пространства, а не разделение данных нескольких организаций.

## Первый редактор опубликованного сайта

Существующая серверная настройка `DATA_EDITOR_EMAILS` сохраняет список
доверенных владельцев служебного входа. Чтобы выдать редактора своему аккаунту:

1. Сначала создайте личный аккаунт Фокуса. Запомните его логин.
2. В отдельном окне браузера без сеанса Фокуса откройте `/login`.
3. Раскройте «Служебный вход для редакторов» и войдите существующей учётной
   записью владельца, уже включённой в `DATA_EDITOR_EMAILS`.
4. Откройте `/account`, найдите созданный личный логин и выберите «Редактор».
5. Вернитесь в обычное окно со своим аккаунтом Фокуса и обновите страницу.

Служебный вход нужен только для начальной выдачи прав при таком размещении.
После этого собственный редактор может управлять командой без внешнего входа.
Первый зарегистрированный посетитель не становится редактором автоматически.

## Первый редактор на своём компьютере

Создайте аккаунт через форму. Затем в терминале из папки проекта выполните:

```sh
npm run auth:editor -- ВАШ_ЛОГИН
```

Команда изменяет роль существующей записи в локальной SQLite. Она не создаёт
пароль и не управляет опубликованной D1. Используется `LOCAL_DB_PATH`, если
он задан; иначе `local-data/incidents.sqlite`. Обновите страницу своего профиля.

## Что уже защищено

- Пароли сохраняются как bcrypt-хэши с уникальной солью, cost 12.
- Форма и сервер проверяют предел bcrypt в 72 байта UTF-8.
- Сеанс действует 8 часов. В cookie — случайный 256-битный токен,
  в базе — только его SHA-256. Повторный вход меняет токен текущего браузера.
- В HTTPS cookie имеет `__Host-`, HttpOnly, Secure и SameSite=Lax.
  Только на HTTP localhost используется отдельная cookie для разработки.
- Выход удаляет сеанс из базы; повтор старой cookie не восстанавливает доступ.
- Вход и регистрация ограничены по частоте через общую базу. Неверный логин
  и неверный пароль возвращают одинаковую ошибку.
- Изменения входа, ролей и настроек ИИ требуют POST с Origin этого сайта.
- Внешние идентификационные заголовки локальный сервер не принимает на веру.

Публичную регистрацию можно закрыть серверным `AUTH_REGISTRATION_OPEN=0`.
По умолчанию она открыта для демонстрации команды. Существующий аккаунт
сможет войти и после закрытия регистрации.

## Ограничения и перенос

Восстановление пароля, смена пароля в интерфейсе, MFA, приглашения и аудит
изменения ролей пока не реализованы. Пользователю нельзя обещать эти функции.
Роль редактора не равна корпоративному администратору МТС.

Аккаунты, хэши паролей и сеансы находятся в рабочей базе и не входят в ZIP.
На новом размещении создайте новые личные аккаунты и назначьте редактора
заново либо отдельно спланируйте защищённый перенос базы. Не копируйте рабочие
сеансы и секреты в открытый архив передачи.

`npm run test:auth` проверяет регистрацию, вход, права, перезапуск, выход и
сохранение настроек ИИ на изолированной временной базе. Тестовые аккаунты
не создаются на опубликованном сайте.
