# МТС Фокус · обзор проекта v17

Изучил ТЗ в `МТС (1).pdf`, основные исходники, выгрузку, заметки о передаче проекта и `материалы/mts_idei.docx`. Файлы `МТС (1).pdf` и `материалы/МТС.pdf` побайтно совпадают.

## Задача из ТЗ

«МТС Фокус» — оперативный дашборд для координаторов массовых ИТ-инцидентов. Он помогает сразу увидеть, что требует внимания, кто занимается инцидентом и сколько времени осталось на восстановление. Инцидент может одновременно входить в несколько групп.

| Требование | Что есть в v17 |
| --- | --- |
| Четыре группы — критические, на координаторах, высокий приоритет, исследование | Группы, счётчики, фильтры и отдельное представление групп. Счётчик фокуса считает уникальные ID. |
| Продукт, время возникновения, исполнитель, статус и срок решения | Поля видны в очереди и карточке. Полная карточка также показывает команду, описание и историю. |
| Заметный критический инцидент и его восстановление | В очереди есть выделение критических и отдельная плашка восстановления. |
| Оповещения о новом критическом и назначении координаторам | Есть уведомления на экране и журнал событий. |
| Автоматически подхватывать изменения файла | Открытый дашборд запрашивает данные каждые 5 секунд. Подхватываются изменения статуса, назначения, приоритета и срока. При временном сбое источника интерфейс может показать сохранённый снимок с предупреждением. |
| Переход в ITSM | Для симуляции предусмотрена учебная карточка. Для исходных данных подготовлен шаблон ссылки по `id` или `sysId`; корпоративный переход МТС ещё предстоит подтвердить. |
| ИИ-анализ | «Фокус AI» использует серверный снимок и выдаёт сводки и подсказки по правилам. Клиент Яндекса и экран настройки готовы, успешный вызов реальной модели пока не подтверждён. |
| Читаемый интерфейс | Есть рабочий экран, видеостена, светлая и тёмная темы. Поиск и фильтры реализованы как дополнительные функции. |

На защите по ТЗ нужно изменить JSON и показать автоматическую реакцию дашборда, появление и решение критического, передачу инцидента координаторам и пользу ИИ-анализа.

## Данные и правила

- Оригинал организаторов хранится в `data/incidents.json`, словарь полей — в `data/attributes.json`. В исходнике 44 записи: 24 активные, 15 завершённых или закрытых, 5 на исследовании. В четырёх группах соответственно 0 / 2 / 1 / 5 записей, всего 8 уникальных в фокусе. В выгрузке 5 продуктов и 22 команды.
- По умолчанию открывается явно помеченная телеком-симуляция МТС. В ней изменены названия продуктов, сервисов и описания, сохранены исполнители, команды, ID, статусы, приоритеты и сроки. Переключатель и `?dataset=source` открывают оригинал. Сценарий «Симулировать событие» действует в текущей вкладке. Для живого прогона используется изменение файла или общей выгрузки.
- Критические и высокие группы включают только активные записи с `priorityId` 4 и 3 соответственно. Группа координаторов определяется по точному названию «КЦ ИТ Координаторы Массовых Инцидентов» и может пересекаться с исследованием.
- `Research` означает, что сервис уже восстановлен и идёт разбор причин. Пустой срок означает отсутствие данных. Для определения статуса приоритет у `stateEnum`, поскольку коды 7 и 10 расходятся между выгрузкой и словарём. `sysId` хранится строкой, чтобы сохранить все цифры.

## Как устроен сайт

| Часть | Где искать |
| --- | --- |
| Рабочий экран, видеостена, графики и взаимодействия | `web/index.html`, `web/app.js`, `web/reference-view.js`, `web/ctrl*.css`, `web/analytics-ui.js` |
| Нормализация, группировка и симуляция | `lib/incidents.mjs`, `lib/mts-simulation.mjs` |
| API, импорт, версии и журнал | `worker/index.js`, `lib/shared-data.mjs`, `drizzle/` |
| Локальный запуск и хранение | `scripts/dev-server.mjs`, SQLite локально, D1 при публикации. Сборка формирует Worker в `dist/server/index.js`. |
| Учётные записи и интеграции | Роль координатора выдаётся при регистрации. Редактор управляет ролями, импортом и настройками ИИ. Основные маршруты — `/login`, `/account`, `/ai-settings`, `/guide`. |

В v17 на основном экране появились две идеи из отдельного документа. «Что проверить координатору» строится по всей текущей выгрузке независимо от фильтров и на исходном наборе показывает 7 уникальных карточек. В правой панели есть следующее действие с объяснением по полям выбранной карточки. Обе функции реализованы в `lib/coordinator-insights.mjs`. Для проверки давности последнего изменения в исходнике нет надёжной метки времени. Для рекомендации конкретной профильной команды нужен справочник владельцев продуктов.
