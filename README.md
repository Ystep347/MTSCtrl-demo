# МТС · Инциденты в фокусе

Прототип дашборда координатора массовых инцидентов МТС. В репозитории
есть учебная выгрузка из 44 записей с обезличенными именами и логинами.
По умолчанию интерфейс показывает вымышленное представление с телеком-сервисами МТС.
Переключатель открывает данные в формате исходной выгрузки. Интерфейс: HTML/CSS/JavaScript;
сервер опубликованного прототипа: Cloudflare Worker с общей базой D1.
Библиотеки Drizzle нужны только для генерации миграций, не для runtime.
Это текущая реализация макета; отдельный FastAPI-сервер пока не создан.

## Запуск

Требуется Node.js 24 с встроенным `node:sqlite` (проверено на 24.22.3).

```sh
npm ci
npm run build
npm run dev
```

Проверки проекта запускаются отдельными командами.

```sh
npm test
npm run validate
npm run test:local
npm run test:auth
```

Откройте `http://localhost:4173`. Локальный сервер перечитывает
`data/incidents.json` на каждом запросе API; страницы проверяют его раз в 5 секунд.
Для примера измените `priorityId` первой записи на `4` и сохраните файл:
запись появится в критических и останется у координаторов.
Смена `stateEnum` на `Resolved` с согласованными `state` и `stateId` уберёт её
из обеих активных групп. После проверки верните исходные значения.

Опубликованный сайт хранит общий набор в D1. При первом обращении он
создаётся из исходных 44 записей; последующие публикации не затирают базу.
Редактор после входа может загрузить JSON через «Загрузить выгрузку»:
предпросмотр показывает изменения, кнопка «Загрузить для всех» сохраняет их.
Другие вкладки проверяют обновления каждые 5 секунд. Версии и события
сохраняются после перезагрузки и закрытия браузера.

Изменение файла в локальном checkout не меняет production. Опциональная
серверная переменная `INCIDENTS_SOURCE_URL` включает чтение общего JSON по
HTTPS при запросах. Если он недоступен или неверен, возвращается последняя
сохранённая версия с предупреждением. Обновление без открытых клиентов и
интеграция с ITSM пока не настроены.

## Данные и правила

- `data/incidents.json` — учебная копия `character_problems(1).json` с обезличенными участниками.
- `data/attributes.json` — неизменённый справочник `incidents_attributes(1).json`.
- `lib/incidents.mjs` — проверка внешнего формата, нормализация, группы, diff.
- `DATA_CONTRACT.md` — поля, статусы, известные расхождения и план для бэкенда.

Исходный набор: 24 активных, 15 завершённых/закрытых, 5 на исследовании.
Группы: 0 критических, 2 у координаторов, 1 активный высокого приоритета,
5 исследований; в фокусе 8 уникальных ID. Есть 5 продуктов и 22 команды.
Кнопка «Все 44» открывает полную таблицу, включая записи вне групп фокуса.
Критические демособытия добавляются отдельно и не выдаются за исходный JSON.

В словаре перепутаны коды 7/10 и не описан Research/20. Смысл статуса берётся
из `stateEnum`, затем из `state`; неоднозначный голый код 7/10 отклоняется.
Три дедлайна null сохраняются пустыми, sysId остаётся строкой.
Заполненный solution у активной записи не считается восстановлением.
В исходных данных нет ссылок на инциденты ITSM и справочника владельцев продуктов.
Переход в ITSM подготовлен: задайте серверный `ITSM_INCIDENT_URL_TEMPLATE`,
например `https://your-itsm.example/incidents/{sysId}` или адрес с `{id}`.
Допустим только HTTPS без учётных данных в URL, значения кодируются как строки.
Реальный адрес нужно получить у МТС. `productUrl` для перехода не используется.
Шаблон влияет на ETag представления, но не меняет raw revision импорта.

## API

- `GET /api/incidents` — нормализованный снимок, meta, revision, source.
  `ETag` / `If-None-Match` позволяют получить 304 без повторной отправки данных.
- `GET /api/auth/me` — текущий пользователь и возможности.
- `POST /api/auth/register` — username, displayName, password; регистрация координатора.
- `POST /api/auth/login` — username, password; собственный сеанс.
- `POST /api/auth/logout` — отзыв сеанса и очистка cookie.
- `GET /api/auth/accounts` — список своих аккаунтов без хэшей, только редактор.
- `POST /api/auth/account-role` — userId, role (coordinator/editor), только редактор.
  Для этих POST нужен Origin текущего сайта; тела JSON до 8 KiB.
- `GET/POST /api/assistant/settings` — состояние/сохранение apiKey, folderId,
  modelUri; только редактор, POST с Origin, до 8 KiB. Секрет не возвращается.
- `POST /api/incidents/import` — замена общего массива, только редактор;
  заголовки `If-Match: "<revision>"`, `Content-Type: application/json`,
  необязательный `X-Source-Name` с percent-encoded именем файла.
- `GET /api/incidents/history?limit=50&before=<seq>&incident_id=<ID>` —
  общий журнал с пагинацией, фильтр по ID необязателен.
- `GET /api/incidents/export?version=<N>` — текущая/предыдущая исходная
  выгрузка, только редактор; без version возвращается текущая.
- `GET /api/assistant/status` — режим без раскрытия секретов.
- `POST /api/assistant/chat` — question, history, contextMode, context; требуется вход.
  Обычный contextMode=server сам читает источник; snapshot разрешён только в client_demo.

Чат работает со всеми 44 записями. Для генерации используется **Alice AI LLM
от Яндекса** через нативный Text Generation API. Вызовов OpenAI в активном
коде больше нет. Нужны API-ключ и каталог Яндекса: редактор сохраняет их на `/ai-settings`.
Альтернатива — серверные YANDEX_API_KEY и YANDEX_FOLDER_ID;
YANDEX_MODEL_URI необязателен (по умолчанию gpt://<folder>/aliceai-llm).

`lib/yandex.mjs` готовит контекст: рассчитанные счётчики, весь краткий каталог
и до восьми подходящих подробных карточек. Режим local явно обозначает анализ
по правилам. Настроенный ключ сам по себе не подтверждает работу модели:
настоящую генерацию подтверждает успешный ответ с provider=yandex.
При ошибке Яндекса показывается явный fallback; на OpenAI перехода нет.
Ключ остаётся на сервере, не включается в снимок, сборку или ответы браузеру.
Форма хранит настройки в app_ai_settings с AES-GCM-256; ключ шифрования
AI_CONFIG_ENCRYPTION_KEY хранится отдельно в окружении. Полные переменные
Яндекса имеют приоритет перед D1. `npm run ai:prepare` подготавливает локальный
ключ шифрования в игнорируемом .env и не выпускает API-ключ провайдера.

Подробная справка: `/guide.html`, также работают `/guide`, `/guide/` и
`/guide/index.html`. Ссылки в верхней панели и внизу открывают справку на
верхнем уровне окна. Серверный код не требует Python для опубликованного
прототипа. Ранее подготовленный пример Ollama в ai-service/ является отдельным
неподключённым примером и не участвует в текущем режиме Яндекса.

Ограничения: 2000 символов вопроса, 500 карточек, 8 сообщений истории,
2 MiB тела запроса. 12 вопросов в минуту на вошедшего пользователя в
пределах одного экземпляра Worker; централизованной квоты нет.
Обычный чат читает актуальный снимок на сервере через loadIncidentData,
применяя выбранный вид source/mts-demo. Клиентский snapshot в обычном запросе
отклоняется. contextMode=client_demo разрешён только как явно обозначенный
анализ временных данных по правилам, без вызова Яндекса. Ответ содержит
revision/version/total и предупреждение при работе по сохранённому снимку.

## Вход и демонстрация

Собственные регистрация, логин/пароль и выход находятся на `/login`.
Обычному участнику не нужен внешний аккаунт. Новый пользователь получает
coordinator; editor назначается отдельно на `/account`. Подробности начальной
выдачи прав на хостинге и локально — AUTHENTICATION.md.

Пароли хранятся как bcrypt-хэши с солью (cost 12), сеансы — 8 часов, в базе
только SHA-256 токена. В HTTPS используется __Host cookie с HttpOnly, Secure,
SameSite=Lax. Есть постоянные ограничения попыток входа и регистрации.
Самостоятельный парольный пользователь не может повысить роль через email
или присланный клиентом role. Регистрацию можно закрыть AUTH_REGISTRATION_OPEN=0.

Необязательный служебный вход платформы сохранён для начального назначения
редактора владельцем из DATA_EDITOR_EMAILS. Он не требуется для повседневной
работы собственных аккаунтов. При переносе ZIP аккаунты/сеансы не включаются.
Нет восстановления пароля, MFA и корпоративного справочника.

Локальный сервер слушает `127.0.0.1` и удаляет входящие заголовки
`oai-authenticated-*`: прямой запрос не может подставить платформенную личность.
Для явного просмотра по LAN можно задать `HOST=0.0.0.0`; тестового редактора
на общедоступном адресе не включайте. Параметры `INCIDENTS_FILE` и `LOCAL_DB_PATH`
позволяют использовать отдельные файлы для проверки. `INCIDENTS_SOURCE_URL`
имеет приоритет перед локальным файлом.

Для локальной проверки редактора добавьте `DEV_EDITOR_PREVIEW=1` в `.env`
и перезапустите `npm run dev`. Только локальный сервер подставляет вымышленного
пользователя. В опубликованный Worker этот режим не включается.

## Общее хранилище

`db/schema.ts` — схема, `drizzle/` — сгенерированные миграции и метаданные.
При изменении схемы выполните `npm run db:generate` и включите новую SQL-миграцию
и метаданные в Git. Публикация применяет их к D1; обработчик запросов не создаёт
таблицы. Применённые миграции не редактируются. `incident_state` содержит текущую
версию, `incident_imports` — все исходные версии, `incident_events` — события.
`app_users`, `app_sessions`, `auth_limits` — аккаунты, сеансы и попытки входа;
`app_ai_settings` — шифротекст настройки Яндекса. Их содержимое в ZIP не включается.

Локальная SQLite-база `local-data/incidents.sqlite` применяет те же миграции
при старте, игнорируется Git и не включается в публикацию. Неизменённый локальный
файл не затирает импортированную через форму версию; новое изменение файла
сохраняется как следующее обновление источника.

Импорт ограничен 500 записями и 1 MiB. Весь файл проверяется до записи.
Обязательная версия `If-Match` и атомарный пакет SQL предотвращают потерю
одновременных изменений: один импорт проходит, другой получает 409 и должен
обновить предпросмотр. Повтор одинакового файла не создаёт событие. Исчезновение
из выгрузки отмечается отдельно от завершения. Предыдущие версии можно скачать
через API; управление восстановлением в интерфейсе ещё не добавлено.

«Запустить демо» и меню сценариев меняют только текущую страницу. На время
демо автоматическая синхронизация приостановлена, это подписано на экране.
«Вернуться к выгрузке» загружает серверный набор. Демособытия не записываются
в JSON и не меняют данные других посетителей. Диалог тоже хранится только
в памяти страницы и очищается при полной перезагрузке.

## Исходники и проверка

`web/` — интерфейс и подробное объяснение на `/guide`.
`worker/index.js` — API, авторизация, анализ, запрос к модели.
Сборка встраивает данные и интерфейс в самостоятельный `dist/server/index.js`.
`dist/` создаётся автоматически; редактировать нужно исходники.
Локальный предпросмотр читает явно заданные настройки Яндекса; production-секреты автоматически не копируются.

`tests/incidents.test.mjs` проверяет 44 записи, семантику статусов,
пустые сроки, длинные ID, обновления JSON, API и чат с полной выгрузкой.
Тесты auth и assistant проверяют права, контекст, ограничения и модельный путь
с подставным ответом API. Реальная LLM этим не проверяется.

## Телеком-симуляция и защита

`lib/mts-simulation.mjs` меняет только демопредставление продукта, сервиса,
описания и решения. ID, исполнители, команды, состояния, приоритеты и времена
берутся из текущей выгрузки. Общий API и база сохраняют её исходный формат.
По умолчанию активна «Симуляция МТС». `?dataset=source` или переключатель
показывает исходные названия. В режиме импорта сравнивается исходный снимок,
а не переименованные карточки. Счётчики и графики вычисляются как прежде.

`data/mts-simulation.json` — отдельный JSON в том же формате с 44 вымышленными
сбоями МТС. Пересоздать: `npm run demo:export`. Нельзя представлять эти сбои
как настоящие события компании. ИИ получает явную пометку simulation.

`/itsm-demo?incident=<ID>` — отдельная учебная страница перехода, доступная
кнопкой «Открыть демо ITSM». Она не подключена к корпоративной системе и не
изменяет данные. Настоящий шаблон ITSM используется в режиме исходной выгрузки.

`DEMO_CHECKLIST.md` содержит прогон защиты. `npm run demo:scenario -- prepare`
создаёт отдельный файл; `serve` запускает его с отдельной базой, а команды
`critical`, `coord`, `deadline`, `resolve`, `high`, `reset` меняют этот файл.
Сайт подхватывает изменения через обычный опрос, а не клиентскую анимацию.

## Подготовка ИИ и оценка готовности (v15)

`AI_CONNECTION.md` — настройка и проверка настоящего Яндекса через страницу редактора.
`npm run ai:check` проверяет наличие настроек без запроса к модели;
`npm run ai:check -- --live` отправляет один реальный запрос и не печатает ключ.
В опубликованном окружении ключ и каталог пока отсутствуют.
`REQUIREMENTS_STATUS.md` — прозрачная рабочая оценка около 80% хакатонного MVP.
Это не оценка жюри и не готовность промышленной системы.

`npm run test:auth` проверяет 9 HTTP-сценариев собственных аккаунтов и
шифрования настроек на временной базе. Всего unit-тестов: 87. Парольный модуль
уже включён в исходники и dist; пересборка из npm: `npm run build:password`.
Лицензия bcryptjs: vendor/bcrypt-LICENSE. Тесты не обращаются к реальному Яндексу.

## Подсказки координатору (v17)

На основном экране «Что проверить координатору» показывает карточки с пробелами
назначения/срока, передачей с координаторов или незавершённым исследованием.
Список относится ко всей текущей выгрузке независимо от фильтров очереди.
В правой панели видны следующий шаг и его основание. Это правила, а не ответ LLM;
подсказки не выполняют назначения и не меняют исходные данные.
Логика: lib/coordinator-insights.mjs; тесты: tests/coordinator-insights.test.mjs.
