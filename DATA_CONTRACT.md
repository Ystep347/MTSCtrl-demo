# Контракт выгрузки МТС

Два полученных файла — JSON-массивы. `character_problems(1).json` содержит
44 записи по 46 полей; `incidents_attributes(1).json` описывает 30 полей.
Данные лежат в character_problems, описание — в incidents_attributes.
В репозитории лежит учебная копия с теми же полями и обезличенными именами
и логинами участников. Исходные материалы организаторов хранятся локально.

## Что передавать фронтенду

| Поле выгрузки | Поле API | Значение |
| --- | --- | --- |
| id | id | Строка INC000021931151, без добавления дефиса |
| sysId | sysId | Строка, не Number: значение превышает точность JS-числа |
| header | title | Заголовок |
| shortDescription / description | summary / description | Описание без домыслов |
| productName | product | Название продукта |
| productMasterId | productCode | Код продукта |
| service / scenarioName | service / scenario | Сервис и сценарий |
| priorityId | priority | 1 low, 2 medium, 3 high, 4 critical |
| stateEnum | status | Правила ниже |
| assignedGroupName | team | Текущая команда назначения |
| assignedEmployee | assignee | Исполнитель |
| submitDate | createdAt | Регистрация, timestamp UTC |
| deadline | dueAt | Дедлайн или null |
| completionDate | resolvedAt | Завершение / восстановление или null |
| lastAssignmentToTeamDateTime | assignedAt | Дата назначения или null |
| isNeedUp | needsFollowUp | true, false или null |
| solution | solution | Показывать как решение только в завершении / исследовании |

JSON API возвращает `incidents`, `meta`, `revision`, `source`,
`pollIntervalMs`, `loadedAt`. В meta есть счётчики групп и предупреждения.
`revision` — SHA-256 исходного набора; время запроса не меняет эту версию.
Сервер возвращает `ETag`, неизменный снимок — 304 по `If-None-Match`.

## Статусы и расхождения

| stateEnum | Текст в выгрузке | stateId в выгрузке | В справочнике | Внутренний статус |
| --- | --- | --- | --- | --- |
| Assigned | Назначен | 0 | 0 | assigned |
| WorkInProgress | Выполняется | 2 | 2 | working |
| Resolved | Завершен | 7 | 10 | resolved |
| Closed | Закрыт | 10 | 7 | closed |
| Research | Исследование ситуации | 20 | Не описан | investigating |

Сначала использовать известный stateEnum, затем текст state. О расхождении
со справочником сообщать. Для голых кодов 7 и 10 смысл неоднозначен — не
угадывать, отклонить запись. Противоречия словаря стоит подтвердить у ментора;
это не мешает отображать текущую выгрузку по её смысловым полям.

Активны только Assigned и WorkInProgress. Resolved и Closed исключены из
оперативных групп, но доступны в полной таблице. Research идёт отдельной
группой и может пересекаться с группой координаторов.

## Четыре группы

| Группа | Условие | Записей в исходном файле |
| --- | --- | --- |
| Критические | priorityId = 4 и активный статус | 0 |
| Координаторы | assignedGroupName точно совпадает с названием команды, статус не Resolved/Closed | 2 |
| Высокие | priorityId = 3 и активный статус | 1 |
| Исследование | stateEnum = Research | 5 |

Команда: `КЦ ИТ Координаторы Массовых Инцидентов`.
Общий счётчик фокуса — количество уникальных ID в объединении групп: 8.
Во всех приоритетах 5 высоких, но только один из них активен: ещё два закрыты,
два находятся на исследовании. Наивысшего приоритета нет.

Остальные низкие/средние инциденты не должны исчезать: полная таблица
содержит все 44 записи. Активных 24, завершённых/закрытых 15, исследований 5.
Продуктов 5, команд назначения 22. Число просрочек зависит от текущего времени;
на 20.11.2026 18:00 МСК просрочено 13 активных записей.

## Особые значения

- У трёх Research deadline = null. Это отсутствие срока, не 1970 год и не просрочка.
- Даты выгрузки имеют Z и иногда доли секунды из 6 цифр. Читаются как UTC,
  отображаются в Europe/Moscow. Даты без зоны требуют согласования; адаптер
  отклоняет их, вместо молчаливой зависимости от часового пояса сервера.
- `0001-01-01T00:00:00` в waitingExitDate — заглушка, а не бизнес-срок.
- sysId — 18-значная строка. Не переводить её в JS Number.
- isNeedUp nullable; строка «Нет» должна означать false, а не Boolean('Нет').
- У всех 24 активных записей заполнено solution с текстом о выполненном решении.
  Не закрывать инцидент по наличию этого текста: главным остаётся статус.
- productUrl пуст во всех записях и по смыслу относится к продукту. Не считать
  его ссылкой на карточку ITSM. Требуется шаблон URL карточки от организаторов.
- assignedGroupName — текущее назначение. Это не справочник владельцев продуктов.
  Для надёжной рекомендации маршрутизации нужна отдельная карта владельцев.

## Обновления для защиты

Локальный сервер читает data/incidents.json на каждом GET /api/incidents.
Фронт опрашивает API раз в 5 секунд. Сравнение по ID замечает новую запись,
команду, приоритет, статус, исполнителя, дедлайн и удаление. Удаление не
объявляется восстановлением. Некорректная версия возвращает 503; интерфейс
оставляет предыдущую корректную версию с предупреждением.

На опубликованном сайте без INCIDENTS_SOURCE_URL используется снимок из
сборки. Для живого общего источника задайте HTTPS URL JSON на сервере.
Затем обновление JSON по этому адресу увидят все посетители. Само изменение
файла на ноутбуке не обновляет опубликованный сайт.

Для защиты: измените у первой записи priorityId на 4; она появится сразу в
двух группах. Затем измените назначение или срок. Завершение задавайте
согласованно: stateEnum = Resolved, state = Завершен, stateId = 7,
completionDate — фактическая дата с Z. Верните исходный файл после проверки.

## Если сервер команда пишет на FastAPI

Сохраните те же внешние поля и контракт GET /api/incidents. Отдельный слой
адаптера проверяет выгрузку; сервис групп считает показатели; сервис изменений
сравнивает версии по ID. Наблюдатель файла или периодическое чтение принимает
только целиком корректную версию. SSE можно добавить вместо polling, когда
основные правила проверены. PostgreSQL понадобится для истории изменений,
пользователей и сохранённых действий; для чтения одной выгрузки на MVP он
не обязателен. Это направление переноса, Python-сервер здесь ещё не создан.

## Отдельная симуляция МТС (v13)

По решению команды интерфейс по умолчанию показывает вымышленные телеком-сервисы
и сбои через `lib/mts-simulation.mjs`. Исполнители и атрибуты групп не меняются.
Это помечено на экране. Исходный JSON/API/общая база сохраняют оригинал.
`data/mts-simulation.json` — отдельная копия с теми же ключами и типами
бизнес-атрибутов; исходный файл не перезаписан. Любая симуляция не является
данными о настоящих происшествиях МТС.
